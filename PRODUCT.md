# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Anyone interested in design decisions: designers choosing a direction for a site, collaborators and clients picking a style together, and AI tools and agents that read the library or receive its briefs and prompts. The usual situation is browsing for a style to build in or to describe to someone else (or to an image model), then taking a copyable brief or prompt away.

## Product Purpose

A browsable reference library of web design languages. Each entry is one style: a reference screenshot, a name, a short and a long description, keywords, a category, a palette, traits (typography, layout, colour, motion) and a ready-to-paste higgsfield.ai image prompt for the style's hero artwork. Success is that someone finds a fitting style quickly and leaves with a brief or prompt they can use without editing.

## Positioning

Two things together that a general inspiration board lacks: a curated, deliberately classified set of design languages built from the owner's own screenshots, and prompt-ready output for every entry (a formatted brief and a hero-artwork image prompt).

## Operating Context

- The owner adds screenshots to `resources/`, then an agent classifies them into entries (see `CLAUDE.md`, "classify the drafts"). New files appear as draft cards under "Unsorted (new)" until classified.
- `data/styles.json` is the source of truth; `data/styles.js` is generated by `npm run sync`.
- Run locally with `npm start` (port 4321, syncs on request) or open `index.html` directly from `file://`.

## Capabilities and Constraints

- Today: category filter chips with live counts, search (press `/` to focus) across titles, descriptions, keywords, traits and prompts, a detail view per style, copy brief, copy image prompt, copy a palette colour, and light and dark themes (OS default, manual toggle).
- Current content: 147 styles, 12 categories plus "unsorted", 135 reference screenshots.
- Plain HTML, CSS and JS only. No build step, no dependencies, no framework. Node 18+ for the scripts.
- Must keep working from `file://`, which is why data ships as `window.DESIGN_LIBRARY` in a script tag rather than a fetched JSON file.
- Only Google Fonts loads from outside; everything else is local.
- Light and dark are both first-class. Every colour comes from a CSS variable defined in `:root` and redefined for dark mode.
- Undecided: whether and where the site is published for a wider audience.

## Evidence on Hand

- 135 real reference screenshots in `resources/` (never delete them) and the 147 written entries in `data/styles.json`, each with palette, traits and an image prompt.
- No testimonials, usage figures or published URL exist. Future work must not invent any.

## Product Principles

- The content is the product: screenshots, descriptions and prompts lead, and the interface stays out of their way.
- Fast to scan, fast to copy. Finding a style and taking its brief or prompt should take a few actions.
- Readable by people and by AI: entry data stays structured, concrete and searchable.
- Stays portable and dependency-free, so the library opens anywhere with no setup.

## Accessibility & Inclusion

No product-specific requirement was stated. Light and dark themes are both required, and the interface is keyboard-operable today (`/` for search, `Esc` to close).
